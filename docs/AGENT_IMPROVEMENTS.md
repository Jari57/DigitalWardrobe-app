# Agent improvements

This release extends the existing workflows without increasing model call limits or introducing autonomous retraining.

- Match verification: exact-identity evidence requires a literal readable model-code token, matching retailer model code and brand, and a consistent visual comparison. Different photos are excluded; conflicting model codes remain labeled alternatives. Missing photo evidence is an unchecked search lead. Evidence tiers determine ordering. Labels never guarantee authenticity, variant, sizing or availability. Stored results are labeled using the same verifier.
- Taste curator: explicitly saved/liked/hidden feedback decays with a 30-day half-life; learning influence is bounded. Equally relevant fresh stories receive priority over already-liked/saved ones. Tracking URL duplicates are removed outside Saved. Existing publisher diversity and explicit clothing preferences remain. UI describes the strongest learned interests. Article prices are unknown, so budget is enforced only in the existing shopping flow, not falsely inferred for editorial stories.
- Dress for my day: optional user-supplied day constraints enter the existing stylist call and cache identity. No weather/location lookup is added. Owned alternatives can be swapped manually without another AI call; locks remain immutable in the swap UI and ownership/locks remain server-validated.
- Closet gaps: incomplete outfits identify missing top/bottom or footwear categories. Existing owned pieces are offered first, with references to selected pieces. Suggestions are category guidance, not guaranteed compatibility or purchase recommendations. Dresses do not generate top/bottom gaps.
- Quality evaluator: `npm run test:agent-quality` runs deterministic regression cases covering identity evidence, conflicts, taste learning, duplication, outfit gaps, swaps, request bounds and ownership. Vercel runs this before migrations/builds. This is a regression gate, not proof of live model accuracy. New anonymized or consented, manually reviewed cases can be added after observed failures; user feedback never rewrites production prompts or deploys code automatically.

No schema migration. Existing model, token, retry and daily budget limits are retained. Shopping/styling cache versions advance because their interpretation changed. Personal feedback remains scoped to the account through existing owner-scoped queries. Live model quality requires a separate, budgeted evaluation; no fabricated improvement percentage is claimed.
